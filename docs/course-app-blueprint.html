Architecture and build plan

Course App Blueprint

A mobile app for building, studying and sharing courses, with AI authoring through the user's own API keys. The repository is empty today, so this is a design for a first build, not a description of existing code.

Local first, no backend

Everything lives on the phone. The only network calls go from the phone straight to the AI provider the user configured.

One schema drives everything

The same course definition validates imports, shapes AI output, fills the prompt file and types the code.

Question types are plugins

Each type brings its own player, editor and grader. Adding a type means adding one folder.

Three provider adapters

Claude, Gemini and one OpenAI-compatible adapter that covers OpenAI, Grok and most others.

System

Architecture

Three layers, each depending only on the one below. The middle layer is plain TypeScript with no screen or operating-system imports, so the schema, grading, import and generation logic can be tested on a laptop in milliseconds and reused if a web or desktop version ever follows.

Content

The course format

"Template" in the brief becomes one versioned file format with three kinds of file: a course, a standalone quiz and a flashcard deck. Each can be created, generated, imported and exported on its own. A file holds content only. Everything personal sits in separate tables that point at content by id, so re-importing an improved course keeps the learner's progress, and a shared file never carries someone's answers.

Three assessment modes, many question types

The brief lists "questions, test, quiz, drag-and-drop". Those mix two different things, so the format separates them. A mode says how an assessment behaves. A type says how one question is answered.

  • Practice sits inside a lesson, gives feedback after every answer and allows unlimited retries.
  • Test closes a lesson, shows the score at the end and has a pass mark.
  • Exam belongs to the whole course, can be timed and can draw a random sample from a question pool.

A standalone quiz uses the same modes. Removing a course, lesson, quiz or deck moves it to a trash with undo.

AI authoring

Two ways to create with AI, one way in

The create form makes a course, a single lesson, a standalone quiz or a flashcard deck. "Prompt for AI" and "Generate" both start from that form and the same prompt builder. They differ only in who carries the prompt to a model. Both results enter the app through the same validation and preview, so a course behaves identically whether it was typed, pasted from a chatbot or generated in the app.

What the prompt file contains

  • The user's choices from the form: what to create, topic, audience, level, language, size, which question types to use, and any source notes.
  • Writing rules for a good course: short lessons, one idea each, every question with an explanation.
  • The JSON schema of the format, generated from the same definition the app validates with.
  • One small complete example, and an instruction to reply with JSON only.

The importer tolerates the usual chatbot habits, such as wrapping JSON in a code fence or adding a sentence before it.

How Generate works

  • One model per run. If several models are checked in Settings, the form shows a picker with the default preselected. With one model there is nothing to pick.
  • Small things in one request. A lesson, a quiz or a flashcard deck comes back from a single call.
  • Courses start with an outline. A fast, cheap request returns the title and lesson list. The user can edit it before anything expensive runs.
  • Then lesson by lesson. Each lesson is its own request, a few at a time, validated and retried on its own. One bad lesson never costs the whole course.
  • Saved as a job. Each step is recorded in the database. If the phone suspends the app, generation resumes from the last finished lesson and a notification says when it is done.

AI inside a quiz

Explain deeper appears on any answered question. It sends the question, the right answer, the learner's answer and the stored explanation to the model, and streams back a longer explanation aimed at the specific mistake.

Check appears on written answers, which is what makes essay questions workable. It sends the question, the author's rubric and model answer, and the learner's text. The reply is structured: a score, what was right, what is missing and how to improve. The result is saved with the attempt, so reopening it costs nothing.

Both use the default model from Settings, with a picker when several are checked. Without a provider, the buttons explain how to add one, and essay questions fall back to showing the model answer for self-rating.

Providers and model detection

In Settings the user adds any number of providers. Each entry has a kind, a label, a key and, for the compatible kind, a base URL. "Test and detect" calls the provider's model list, filters out models that cannot write text, and shows the rest as checkboxes. Checked models are the ones offered in the create form and inside a quiz, and one of them is the default.

Adapters also translate provider-specific endings, such as a refusal or a reply cut off at the length limit, into one shared set of errors the screens know how to explain.

Study tools

Focus mode, Pomodoro and notifications

Focus mode

The lesson goes full screen, navigation hides, the screen stays awake and in-app banners are held back. Leaving the app during a session is recorded as an interruption, which the stats show honestly.

Focus mode stays inside the app. It does not touch the phone's Do Not Disturb setting.

Pomodoro

Focus, short break, and a long break after every fourth round. Lengths are adjustable. The timer stores the moment the phase ends instead of counting ticks, so it stays correct when the app is in the background or killed. A local notification is scheduled for that moment.

Notifications

All local, since there is no server to send them.

  • Daily study reminder at a chosen time, skipped on days already studied.
  • Pomodoro phase finished.
  • Review questions are due.
  • Streak about to break.
  • Course generation finished.

One planner owns all of them. It works out which notifications should exist from settings and current state, compares that with what is scheduled, and adds or cancels the difference. This matters because iOS keeps at most 64 pending local notifications per app, and Android 13 and later needs the user's permission before any are shown.

Build order

Plan

Nine steps, each leaving the app usable. The order follows the dependencies. The schema comes first because everything reads it. Import comes before Generate because Generate reuses its validation and preview. Sizes are relative: S is a few days of focused work, L is a few weeks.

  1. Foundation S Built

    Expo project with strict TypeScript, linting, tests and continuous integration. Tab navigation shell, light and dark theme, SQLite with migrations, translation scaffolding. Two short technical checks still open, because they need a real device: streamed HTTP responses and drag-and-drop.

    Done when

    The empty app runs on iOS and Android and every commit is checked automatically.

  2. Course format and library M Built

    Schema version 1 for courses, lessons, standalone quizzes and flashcard decks, with the first seven question types. Blank templates and one bundled sample of each kind. Library listing all three kinds with search and filters, create, rename, mark as favorite or completed, remove to trash, restore.

    Done when

    The sample course, quiz and deck appear in the library and survive every create, mark, remove and restore action.

  3. Lesson player and quiz engine L Built

    Rendering of lesson blocks. The question type registry with seven types, including flashcards and essays rated against a model answer. Practice, test and exam modes, attempts, scoring, results screen, progress and resume.

    Done when

    A learner can finish the sample course from first lesson to final exam and see a score, take the sample quiz and study the sample deck.

  4. Import, export and Prompt for AI M Built

    File reading and writing for courses, single lessons, quizzes and decks. Import with preview, clear error messages, a choice to replace or duplicate when the item already exists, and a full backup. The create form for all four, the prompt builder and sharing of prompt.md.

    Done when

    A course written by an outside chatbot from the prompt file imports without hand editing.

  5. Editor and drag-and-drop types L

    Editing of courses, lessons and blocks, with reordering. An editor for every question type. The three drag-based types: matching, ordering and sorting into groups.

    Done when

    A complete course using every question type can be built on the phone with no file involved.

  6. Settings and providers M

    User name. Provider list with add, edit and remove. Keys in the secure store. "Test and detect" for models, checkbox selection and a default model.

    Done when

    Keys for three different providers are saved, each lists its models, and none of the keys appears in a backup file.

  7. Generate, Check and Explain deeper L

    The three adapters. A model picker in the create form. One request for a lesson, quiz or deck, and outline then lessons for a course, with saved and resumable jobs. Check for written answers and Explain deeper in the quiz player. Token usage shown per run.

    Done when

    A course, a quiz and a deck are each generated with a model picked in the form, an interrupted course run finishes after reopening the app, and an essay answer comes back with a score and feedback.

  8. Focus, Pomodoro and notifications M

    Focus view, the timer state machine, session log, the notification planner and the permission flows on both platforms.

    Done when

    A timer started before the app is closed still rings on time, and reminders stop on days already studied.

  9. Review, stats and release M

    Review queue for missed questions and flashcards, streaks and study statistics, first-run walkthrough, accessibility pass, store builds.

    Done when

    Test builds are in the hands of real users on both stores.

Beyond the brief

Suggestions

Spaced review of what you got wrong

Every missed question joins the flashcards in one daily queue and returns after a day, then three, then a week. It turns one-off quizzes into retention, and it suits a project named anki. Planned in step 9.

Quiz or flashcards from a lesson

One tap on any lesson generates a standalone quiz or deck from its text. It reuses the create form with the lesson filled in as source material.

A "fix this" prompt for failed imports

When a pasted course is invalid, the app writes a short prompt listing the exact problems. The user pastes it back to the chatbot and gets a corrected file.

Custom base URL for providers

One extra text field lets the same adapter reach OpenRouter, a company gateway or a model running on the user's own computer.

Create from your own material

Paste notes or an article into the form as source text, and the course is built from that instead of the model's general knowledge. Cheap to add once Generate works.

Usage shown after every AI action

Generate, Check and Explain deeper each show the tokens they used. People paying for their own key can see which habits cost money.

Left out of the first version on purpose: accounts, cloud sync, a public course catalog, audio and video inside lessons, running several models at once to compare results, and anything that changes phone-wide settings during focus. Each can be added later without changing the file format.

Decisions that are yours

  1. Framework. The plan assumes Expo with React Native. Flutter would also work, but the schema could no longer be shared directly with the app code. Say so if you prefer Flutter or fully native apps.
  2. Scores from Check. The plan lets a score given by the model count toward a test result, marked as AI-graded. Say if it should be advice only.
  3. Essays without a key. The plan shows the model answer and lets the learner rate themselves. Say if essay questions should be hidden instead.
  4. Media. The plan covers text, code and images in the first version, with no audio or video.
  5. Interface languages. English only at launch, or more.
